## 一、问题

`03-正文/` 全部 59 章的对白引号用的是 **ASCII 半角双引号 `"`**，全书 **5326 处**，全角 `“”` 与直角 `「」` **各 0 处**。另有半角单引号 **104 处**，用于对白内部的二次引用。

中文正文在番茄与起点上会把半角双引号渲染成一根竖直的短棍，两侧不分左右，成段对白读起来会明显不对。

**机检为什么一直不报。** `check-format.mjs` 查的是七项 markdown 装饰——加粗、斜体、引用块、分隔线、标题、列表、反引号，不含标点。`check-facts.mjs` 查的是名词表里登记过的禁用词、人名、数值、年份，也不含标点。

`agents/triage-labels.md` 的盲区表里已经有「半角标点」这一行，但它写的是「当一侧是引号时」——**它防的是引号旁边的逗号，没有防引号本身**。所以这一处不是被漏判，是从来没有被登记过。这正是那张表下面那条推论说的形状：一行给假安心的规则比没有那一行更危险。

## 三、为什么这次可以机械转换

一般情况下「按出现顺序奇偶转左右引号」是不安全的，因为嵌套引用会打乱奇偶。**本仓不存在这个风险**，理由是可验证的两条：

1. **每一章的双引号个数都是偶数**，说明没有一处漏配。
2. **对白内部的二次引用全部使用半角单引号，没有一处用双引号嵌套双引号。** 样板是 `第050章:133`：

> "一件器的状况报告里没有'锈蚀面积占比'这一栏。"

所以「第奇数个 `"` 转 `“`、第偶数个转 `”`」在本仓是**可证明正确**的，不是概率上大概对。单引号同理。

一行里出现三个以上引号的片段有 422 处，那不是嵌套，是一行里两句对白夹一句提示语（`"你说的挨个。"他说，"挨哪个。"`），奇偶顺序照样落对。

## 四、脚本

写成一次性脚本而不是直接改 `check-format.mjs`。理由是这是**一次性迁移**，不是长期检查；长期那一半见第六节。

```js
// scripts/fix-quotes.mjs  一次性迁移，跑完即可删
import { readdirSync, readFileSync, writeFileSync } from 'node:fs'
import { join } from 'node:path'

const DIR = '03-正文'
const dry = process.argv.includes('--dry')

for (const name of readdirSync(DIR).filter((n) => /^第\d{3}章-.*\.md$/.test(n))) {
  const path = join(DIR, name)
  const src = readFileSync(path, 'utf8')

  let d = 0
  let s = 0
  const out = src.replace(/["']/g, (ch) =>
    ch === '"' ? (d++ % 2 === 0 ? '\u201c' : '\u201d') : s++ % 2 === 0 ? '\u2018' : '\u2019',
  )

  if (d % 2 !== 0 || s % 2 !== 0) {
    console.error(`${name} 引号不成对（双 ${d} 单 ${s}），跳过`)
    continue
  }
  console.log(`${name}  双 ${d}  单 ${s}`)
  if (!dry) writeFileSync(path, out, 'utf8')
}
```

**奇偶不平的章直接跳过并报出来，不猜。** 现在一章都不会触发，但拉厚之后可能有人写漏一个引号——那时它就是这一轮唯一有用的一句代码。

写回用 `writeFileSync(..., 'utf8')`，不经过 PowerShell。`agents/workflow.md` 的本机环境那一节写死了不许用 `Set-Content` 改中文文件。

**这是一个全库派生态命令**——扫当前树再写回去。`agents/parallel-sessions.md:54` 写着这一类不得单方面跑，因为它的输入包含别人写到一半的部分。

| 项 | 定案 |
| --- | --- |
| 谁跑 | **通道 1（总编）**，一个人跑，不外派 |
| 什么时候跑 | **等 21~40 拉厚四段全部 `report_task(done)` 之后**，且当时没有任何通道在写 `03-正文/` |
| 跑之前 | `git status` 确认 `03-正文/` 没有别人未完成的改动；先 `--dry` 跑一遍看输出的章数与引号数 |
| 跑之后 | 人工过 `git diff -- 03-正文/`，抽三章逐字看对白；再跑 `npm run check` 要求退 0 |
| 出问题怎么退 | 这棵树长期不提交，`git checkout -- 03-正文/` 会把别人的活一起冲掉。**所以跑之前必须先把 `03-正文/` 逐文件 `git add`**，出事用 `git restore --staged --worktree` 只退这一个目录 |

**已经通知四个主笔通道：拉厚期间不许动引号。** 四份任务书里都写了这一条，原话是「你现在改会撞车」。

**顺序不能反。** 先转引号再拉厚，等于让四个通道在一棵已经改过 5326 处的树上写新句子，他们新写的对白仍然会是半角（编辑器不会自动跟），跑完还得再跑一次。

## 六、跑完之后要加的那条检查

**一次性脚本跑完就删，但检查要留下**，否则下一章又写回半角。

按 `agents/domain.md`「要加一条检查，去名词表加一行，不要改脚本」的规矩，本条是例外——**名词表管的是设定概念，管不了标点**。所以这一条加在 `check-format.mjs` 的装饰规则表里，作为第八项：

```js
{ label: '半角引号', canFix: false, test: (line) => /["']/.test(line) },
```

`canFix: false`，因为 `--fix` 会写回整个 `03-正文/`，而这一条的正确修法是逐章确认奇偶。

**加它之前先确认它真的会命中**（`agents/triage-labels.md` 那条推论）：迁移跑完之后正文里应当一处都没有，退 0；随便往任何一章塞一个 `"` 应当立刻退 1。两个方向都验过再提交这一行。

## 七、这份方案没有覆盖的

- **`01-设定/`、`02-大纲/`、`04-审校/` 里的半角引号不动。** 那些不是正文，不上平台，改它们只会把 diff 撑大并干扰别人的引用匹配串。
- **章名与文件名不动。**
- **`src/` 那个在线书架不用改。** 它只消费 `03-正文/`，转换之后自然显示全角。
- **没有验证番茄与起点的编辑器对全角引号的具体渲染。** 这一条是按中文出版通例定的，不是实测。**要实测得等真正上传一章。**

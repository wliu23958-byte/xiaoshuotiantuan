# 正文排版规范

## 为什么这条规矩存在

正文最终要粘进番茄、起点、七猫的编辑器。**那些编辑器不解析 markdown。** 你写的 `**他死了**`，读者看到的就是带星号的 `**他死了**`；`---` 会变成三个横杠；`>` 会变成一个尖括号顶在句子前面。

这不是审美问题，是会直接砸在读者脸上的显示事故。

首次全库扫描的结果：15 章里 **加粗 109 处、分隔线 85 处、引用块 175 处**，无一章幸免。

## 硬规则

正文段落里**不允许出现任何 markdown 语法**：

| 禁止 | 用什么代替 |
| --- | --- |
| `**加粗**` `__加粗__` | 靠文字本身。写不出重量就是句子的问题，加粗救不了 |
| `*斜体*` | 同上 |
| `> 引用` | 直接写成正常段落。人物说的话用引号，不用引用块 |
| `---` 场景分隔 | 独占一行的 `※　※　※`（阅读器认得它，会渲染成一条居中细线） |
| `## 小标题` | 正文不分小节。要断就用场景分隔 |
| `- 列表` `1. 列表` | 改写成叙述句 |
| `` `代码` `` | 去掉反引号 |

**唯一允许的 markdown**：文件首行的章节标题 `# 第N章　标题`（全角空格分隔），以及 frontmatter。

## 一个踩过的坑：本站阅读器和外发平台要的东西不一样

`src/lib/utils.ts` 的 `toBlocks()` 是本站阅读器的迷你解析器，它**认得** `---`、`>` 和 `**加粗**`，分别渲染成分隔线、引用块和粗体。也就是说，正文里的 Markdown 在**本站是有效的**，只在番茄/起点无效。

清理装饰的时候要意识到这个取舍：**你剥掉的是本站阅读器真在用的语义**。第一次全库清理就翻过车——把 `---` 换成 `※　※　※` 之后，阅读器不认识新标记，把它当普通段落渲染，套上 2em 首行缩进，在页面上看起来像一行乱码。

现在 `toBlocks()` 已经同时认 `---` 和 `※　※　※`，这个具体的坑填上了。但原则要记住：**改正文里的标记之前，先去 `toBlocks()` 确认阅读器认不认。**

长远的正解是留一个导出步骤，本站保留富语义、外发时转纯文本，而不是让源文件迁就最弱的那个平台。这件事还没做。

## 结构规则

脚本同时会做一遍结构体检，这几条也是硬的：

- 文件名 `第NNN章-标题.md`，**序号三位补零**。加载器按文件名自然序排，序号不能跳、不能重
- 首行 `# 第N章　标题`，章号和标题之间是**全角空格**
- **文件名里的标题要和首行标题一字不差**
- 应用保存过的章节改成 frontmatter 形式，那就必须有 `标题` 字段

## 检查脚本

写完或改完任何章节，跑一次：

```bash
node .cursor/skills/novel-chapter-format/scripts/check-format.mjs
```

装饰问题列出文件、行号、原文；结构问题单列一节。任一有问题就退出码 1。

**Windows / PowerShell 必读**：默认代码页会把中文输出打成乱码。先设一次编码再跑：

```powershell
[Console]::OutputEncoding=[Text.Encoding]::UTF8; node .cursor/skills/novel-chapter-format/scripts/check-format.mjs
```

自动修正（只处理能安全机械替换的三类：加粗、分隔线、引用块）：

```bash
node .cursor/skills/novel-chapter-format/scripts/check-format.mjs --fix
```

`--fix` 只动加粗、分隔线、引用块三类，**结构问题一律不自动改**（改文件名要连带改加载顺序，风险太大）。

`--fix` 之后**必须再跑一次无参数版本确认干净**，并且人工过一遍 diff——脚本不判断语义，它不知道你那个加粗是不是真的想强调。

一个实测过的验收办法：改完之后比对修改前后的**汉字数**，应该分毫不差。差了就说明误删了正文，不是只删了符号。

## 两种合法的章节头，别混

| 形式 | 来源 | 样子 |
| --- | --- | --- |
| H1 标题 | 团队手写 | 首行 `# 第一章　断口`，无 frontmatter |
| frontmatter | 应用里编辑过 | `标题:` `更新:` 字段，无 H1 |

加载器 `src/lib/content.ts` 两种都认。但要注意：**一旦用应用的章节编辑器保存过，H1 形式会被自动转成 frontmatter 形式**，因为 `chapterMarkdown()` 就是那么写的。所以同一部作品里两种形式会混着出现，这是正常的，不要手工去"统一"它们，改回去下次保存还会变。

## 引号

全书 15 章统一使用半角 `"`，零处全角 `“”`。这是既成事实，**不是缺陷**。

要改就整库一次性改，不要一章一个样。改之前先在黑板上过一遍——这是全局风格决定，不是排版清理。

## 工作流

写完一章之后：

1. 跑 `check-format.mjs`
2. 有问题就 `--fix`，然后人工看 diff
3. 再跑一次确认退出码 0
4. 提交

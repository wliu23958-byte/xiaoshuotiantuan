# 写一章正文

## 顺序不能乱

```
- [ ] 1. 对表：读时间线台账，确认本章涉及的年份与年龄
- [ ] 2. 读纲：找到本章在细纲里的条目，抄下"本章新增信息"和"不许提前泄露的信息"
- [ ] 3. 读前一章正文：接住上一章的钩子和情绪落点
- [ ] 4. 写
- [ ] 5. 排版自检
- [ ] 6. 回写台账
```

**第 1 步不许跳。** 第一卷初稿全线崩过一次，原因就是有人凭记忆写年份。

## 各章在哪

| 卷 | 章 | 细纲 |
| --- | --- | --- |
| 一 | 1~30 | `02-大纲/第一卷细纲.md` |
| 二 | 31~150 | `02-大纲/第二卷细纲.md` |
| 三 | 151~270 | `02-大纲/第三卷细纲.md` |
| 四 | 271~390 | `02-大纲/第四卷细纲.md` |
| 五 | 391~500 | `02-大纲/第五卷细纲.md` |

支线单元的器物与案情在 `02-大纲/非盟器单元案例库.md`，卷细纲里只标章段与钩连点。

## 文件

放在 `03-正文/`，文件名 `第NNN章-标题.md`，序号三位补零。加载器按文件名自然序排，所以序号不能跳也不能重。

首行写 `# 第N章　标题`，中间是**全角空格**，而且**文件名里的标题要和首行标题一字不差**。不要写 frontmatter——手写章节用 H1 形式，应用保存时会自动转换。

这几条排版脚本会自动查（序号断号、重号、全角空格、文件名与标题不一致），不用自己数。

## 写的时候盯住五件事

**一、开头 300 字内出冲突。** 不写背景说明，直接切事件中心，用对话代替旁白。

**二、沈砚话极少，一次不超过两句。** 急了也不提高声音。唯一能长篇大论的时候是讲器——但讲自己的能力不算讲器。

**三、每一道工序对应一段真相的解锁。** 修复进度就是解谜进度条。工序、病害名称、材料必须真实，器物可以虚构，专业常识不能虚构。

**四、姜宁的仪器是可信度锚点。** 沈砚"看见"的东西，最后要被她的数据验证一次。读者不必信沈砚，读者信数据。但她不能连续三次都成功——该让她测不出来的时候就让她测不出来。

**五、章末留钩子，独立成段。** 要么颠覆认知，要么情绪炸裂，要么承诺惊人。番茄的实测数据是设了钩子的章节下一章打开率高 53%。

## 字数

**口径已定：3000 字/章**，全书按长版 150 万字 / 约 500 章规划。免费平台发布时再按 1500~2000 拆章，那是发布环节的事，写的时候不用管。

注意：**已写的第 1~15 章平均只有 1745 字**，是早期按免费平台长度写的，和现在的口径不一致。这批旧章要不要回头补写，是单独的决定，别在写新章的时候顺手改。

## 排版

正文里**不许出现任何 markdown 装饰**——加粗、斜体、引用块、分隔线、小标题、列表、反引号，一个都不行。番茄和起点的编辑器不解析 markdown，这些符号会原样砸在读者眼前。

场景切换用独占一行的 `※　※　※`。

写完跑一次检查（Windows 先设 UTF-8 编码，否则输出是乱码）：

```powershell
[Console]::OutputEncoding=[Text.Encoding]::UTF8; node .cursor/skills/novel-chapter-format/scripts/check-format.mjs
```

详细规则见 `novel-chapter-format` skill。

## 收尾：回写台账

**这一步最容易忘，忘了就是下一次崩盘的种子。**

如果本章发生了入器，回 `01-设定/时间线台账.md` 的"入器次数与沾锈台账"补一行：第几次、第几章、什么器、什么触发、现实里经过多久、沾锈到多少。

沾锈必须单调递增。本卷的目标值在对应卷细纲的台账表里。

**还有一条更容易漏的**：本章对话里只要出现了量化值——百分比、秒数、毫米、次数——都要回写台账，哪怕它看起来只是随口一提。

已经栽过一次：第 13 章的"沾锈从 0.9 涨到 1.8"和"上回你停了十七秒"，当时只活在那一句对话里，台账查不到。**一个只存在于正文对话里的数字，等于没有定义**，下一个写手会自己编一个新的出来。

如果本章新立了任何设定——人名、地名、器物、规则——写进黑板 `kind=contract` 锁定，并通知设定师登记。**大纲一旦引用就得锁定**，不锁的话下一个人会写出第二个版本。

## 写完之后

初稿不等于定稿。交给审校之前可以自己先用 `novel-chapter-grill` skill 过一遍，能省一轮返工。

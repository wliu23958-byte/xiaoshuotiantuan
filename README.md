# 小说天团 · 在线书架

把 `03-正文/` 目录直接变成可读书架的本地应用。写作产物是 Markdown 文件，
书架、阅读器、章节编辑器都围绕这些文件工作，不存在第二份数据。

技术栈：React 19 + TypeScript + Vite 8，除脚手架自带依赖外没有引入任何第三方库。

## 快速开始

```bash
npm install
npm run dev
```

## 内容从哪来

书架的唯一数据源是 `03-正文/`，支持两种摆法：

```
03-正文/
├── _book.md                        # 作品元信息（可选）
├── 第001章-断口.md                  # 平铺：整个目录就是一部作品
├── 第002章-力是从里面出来的.md
└── 长夜行舟/                        # 或者一部作品一个子目录
    ├── _book.md
    └── 01-001-冰面上的敲门声.md
```

### 章节文件

主笔怎么写就怎么放，不强制 frontmatter。首行的 `# 标题` 会被当作章节名并在正文里去掉：

```markdown
# 第一章　断口

断口合上的那一瞬间，沈砚听见有人在他耳边说话。

"别修了。"
```

也可以用 frontmatter 显式指定，优先级高于 `#` 标题：

```markdown
---
标题: 第一章 · 断口
更新: 2026-08-08
---
```

阅读器认识稿子里实际用到的三种记号：`---` 渲染成分场分隔线，`> ` 渲染成引用，
`**加粗**` 渲染成着重。其余按段落原样排版。

### `_book.md`

```markdown
---
书名: 合缝
作者: 小说天团
标签: 悬疑, 考古, 单元剧
状态: 连载中          # 草稿 / 连载中 / 已完结
色调: 158             # 0-359，决定封面渐变色相
更新: 2026-08-08      # 可省略
---

一件送来五年、捐赠人明令"永远不许修"的西周晚期残盉。
```

省略 `_book.md` 也能跑，书名会退化成目录名。

几条约定：

- 章节按**文件名**排序（数字部分按数值比较），排序即阅读顺序
- 文件名只负责定位和排序，显示用的是标题；改标题不会重命名文件
- 目录名是作品标识，重命名目录会让已有的阅读进度对不上

## 功能

- **书架**：搜书名/作者/标签，按连载状态筛选，顶部「继续阅读」带进度条
- **阅读器**：宋体排版首行缩进，字号行距可调，白天/纸色/夜间三主题，目录弹层，左右方向键翻章，滚动位置自动记住
- **章节编辑**：极简写作面，停止输入 600ms 后自动写回对应的 `.md` 文件，实时字数段落统计
- **作品管理**：新建/编辑/删除作品与章节，全部直接反映到 `03-正文/`

阅读进度和排版偏好存在浏览器 localStorage（键 `xiaoshuotiantuan:reading:v2`），
和正文完全分开，清空它不会动到任何文件。

## 编辑能力只在开发模式下可用

浏览器不能直接写磁盘，读写都靠 `vite.config.ts` 里的 `xst-content-writer` 插件：

| 接口 | 作用 |
| --- | --- |
| `GET /__content/list` | 实时列出 `03-正文/` 下的全部 Markdown |
| `POST /__content/write` | 写入章节或 `_book.md` |
| `POST /__content/remove` | 删除某个章节文件，或整个作品子目录 |

`dir` 和 `file` 都会校验：不允许路径分隔符、`..` 和空字节，`file` 必须以 `.md` 结尾，
且拒绝删除内容根目录，写入范围被限制在 `03-正文/` 一层之内。

开发模式下书架走 `GET /__content/list` 实时读盘，不走 `import.meta.glob`，
因为内容目录被排除在文件监听之外（否则自动保存会不停触发整页刷新，打断正在打字的人），
模块缓存会让新建的章节读不到。别人在编辑器里改了文件，点顶栏「重新载入」即可。

`npm run build` 出来的产物没有这个插件，内容在构建时打包成快照，是纯只读书架，
所有编辑入口自动隐藏。

## 与写作流程的关系

`团队手册.md` 定义了设定师、大纲师、主笔、审校的分工，产出分别落在
`01-设定/`、`02-大纲/`、`03-正文/`、`04-审校/`。这个应用只消费 `03-正文/`，
所以主笔无论是用编辑器直接写文件，还是在应用里写，结果是同一份东西。

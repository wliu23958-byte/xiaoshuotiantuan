# 问题登记在哪

本仓没有工单系统。发现的问题分三个通道走，选错通道的后果是问题被记在一个没人会再看的地方。

## 三个通道

| 通道 | 存活期 | 装什么 |
| --- | --- | --- |
| `04-审校/` 的审校记录 | **永久** | 已经查过的结论。包括判定为「故意保留」的疑似矛盾 |
| 黑板（`post_to_blackboard`） | 一个阶段 | 尚未有结论的风险、待确认的契约、刚锁定的设定 |
| PChat 任务（`delegate_task` 等） | 一次交付 | 「谁去把它改掉」这件事本身 |

判据很简单：**结论进审校记录，未决进黑板，动作进任务。** 一个问题通常会依次经过三个通道，不是三选一。

## `04-审校/`

一卷一档，或一轮一档。现有的命名就是约定：

```
04-审校/
├── 第一卷审校记录.md          # 正文审校，第一轮
├── 第一卷审校记录（二）.md     # 同一卷的后续轮次，中文序号加括号
├── 第一卷审校记录（三）.md
└── 第一卷章纲审校记录.md      # 章纲审校，与正文审校分开存
```

**正文审校与章纲审校分成两份，不要合并。** 它们查的东西不一样（正文查落地文字，章纲查结构与字段），生命周期也不一样——章纲会在正文写出来之前被改很多轮。

单章的审校结论不单独开文件，追加到所在卷那一份的末尾。五百章开五百个文件，等于没记。

### 一条记录长什么样

格式由 `novel-chapter-grill` skill 定，四节：致命伤 / 硬伤 / 复核通过 / 留给主笔的提醒。分级口径见 [triage-labels.md](./triage-labels.md)。

**「复核通过、不用改的」那一节不要省。** 它列出你专门查过、确认没问题的地方，决定了下一轮审校能不能少走一遍。省掉它，下一个人会把同样的交叉比对重做一次，还可能得出相反结论。

第一卷做过两轮全文人工审校，每轮都是全文交叉比对时间锚点、数字、专业细节。九万字做得动，四十五万字做不动——每新增一章，要比对的既有事实就多一层。这一节是唯一能让复核成本不按 O(n²) 涨的东西。

## 黑板

三种 `kind`，含义不重叠：

- **`contract`** —— 已经锁定的设定或命名。写正文写章纲之前 `get_blackboard`，别凭记忆
- **`decision`** —— 想改一条已锁定的东西，先在这里提，等总编确认
- **`risk`** —— 发现了问题但**不该由你拍板**。涉及设定或情节走向的一律进这里，同时 `send_to_session` 通知责任人

新立任何设定——人名、地名、器物、规则——立刻 `post_to_blackboard`（`kind=contract`）并通知设定师登记进名词表。**大纲一旦引用就得锁定**，不锁的话下一个人会写出第二个版本。

追加优先用 `mode:"append"`。全组每轮都要看见的少数几条用 `pin_group_note` 钉住，只有 5 个槽位，留给长期约束和已冻结的契约，不要拿来播报进度。

## PChat 任务

任务本身就是登记，不用再往文件里抄一遍。选哪个原语看形状：

| 形状 | 用 |
| --- | --- |
| 一批互相独立的活（十章各自的初稿、一卷各章的机检复核） | `push_backlog`，空闲成员自助认领 |
| 有依赖的多步（设定 → 章纲 → 正文 → 审校） | `submit_plan` 一次提交 DAG |
| 临时单点委派 | `delegate_task` |

**任务书要写清 `objective` 和 `acceptance`。** 章纲交给主笔时必须写明**本章新增信息**和**本章不许提前泄露的信息**，后者直接进 `boundaries`——这是大纲师对主笔的交接契约，漏了就等于放任提前泄底。

交付物在 `report_task` 时登记进 `artifacts`（章节文件路径、字数），不要只在 `result` 的正文里提一句路径——那样下游节点拿不到。

## 什么不进任何通道

**别人正在改的文件里的问题**，以及**你没打开源文件确认过的问题**。

第一类会在对方那一轮里自己消失，报了只会驱使他去看一个正在变的地方。第二类是纯粹的负收益，[domain.md](./domain.md#冲突按什么顺序裁) 里那个「六道 / 八道」的误报就是它——差点改错正文。

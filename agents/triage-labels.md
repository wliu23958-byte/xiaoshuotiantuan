# 问题分级

审校记录里的严重度、归属和状态各是一套词。混着用会让「这条到底要不要现在改」变成每次重新讨论一遍的事。

## 严重度

`novel-chapter-grill` 的输出格式就按这四级分节。

| 级别 | 判据 | 处置 |
| --- | --- | --- |
| **致命伤** | 会让主线根基塌掉 | 停下手上的活先修。**没有就写「无」，不要凑** |
| **硬伤** | 读者会发现的错，但不动摇结构 | 本轮内改掉 |
| **复核通过** | 专门查过、确认没问题 | 只记录，不改。这一节不许省 |
| **提醒** | 给下一章的前瞻建议 | 最多三条 |

致命伤的门槛比直觉高。判据是「按这条算下去，后面的主线还成不成立」——时间线两套并存让爷爷得在死后一年补人，那是致命伤；某章少了个章末钩子，那是硬伤。

**「复核通过」不是没找到问题的意思。** 它是一条正向断言：这个点我查了，它是对的。所以它必须像报错一样带 `文件:行号`，否则下一轮审校无法据此跳过。

## 归属：这条该改哪边

每条问题除了严重度，还要判一个「改哪边」。默认顺序是硬的：

```
正文 ← 大纲 ← 设定
```

**箭头指向让步方向：设定让给大纲，大纲让给正文。** 正文是最贵的资产，改一句要牵动上下文和读者记忆；大纲和设定是活文档。只有正文**自相矛盾**时才动正文，而且挑改动面最小的那一处下手。

| 归属 | 什么时候是它 |
| --- | --- |
| `设定` | 台账、名词表、核心设定与已落地的正文对不上 |
| `大纲` | 细纲 / 章纲声称的事实，正文里是另一个样子 |
| `正文` | 正文自相矛盾，或与已锁定的契约冲突且契约不该让步 |
| `待裁` | 涉及情节走向，审校不该自己拍板 |

`待裁` 的一律进黑板 `kind=risk` 并 `send_to_session` 通知责任人，不要自己改完了事。

## 谁能自己改

| 能自己改 | 必须先报 |
| --- | --- |
| 错字、标点、半角混入 | 任何设定级改动 |
| 与台账对不上的数字、年份 | 情节因果与人物动机的调整 |
| 排版（markdown 装饰、全角空格、章号） | 已锁定契约的修改 |

分界线是**这条改动会不会让别人手上的东西作废**。改一个错字不会，改一条设定会。

## 黑板 `kind`

| kind | 含义 |
| --- | --- |
| `contract` | 已锁定的设定或命名。写之前先 `get_blackboard` |
| `decision` | 请求改一条已锁定的东西，等总编确认 |
| `risk` | 发现了问题但不该由你拍板 |

## PChat 任务状态

任务状态由系统维护，这里只记本项目关心的几个转换。

| 状态 | 你该做什么 |
| --- | --- |
| 收到任务 | 第一时间 `ack_task`。接不了就 `decline` 并写原因，别沉默 |
| 开工 | 立刻 `report_task_progress`，之后每换一个阶段报一次 |
| 要跑长活 | `report_task_progress` 带 `holdMs`。全卷机检、大批量改写都算 |
| 干不完 | `report_task(status="returned")` 退约，写清已经做到哪 |
| 完成 | `report_task(status="done")`，`artifacts` 里列文件路径与字数 |

**沉默是唯一会让工作被丢掉的行为。** 系统只看得见 `report_task_progress`，本地编辑文件和跑脚本它一概看不到。超时两次，任务会被转给别人，你已经做的部分全部作废。

## 机检退出码

三个脚本的退出码语义不一样，别混着判。

| 脚本 | 干净时 | 有问题时 |
| --- | --- | --- |
| `check-format.mjs` | 0 | 1 |
| `check-facts.mjs` | 0 | 1 |
| `check-outline.mjs` | 0 | 1 |
| └ 其中**章名比对**（2026-08-15 加） | 0 | 1（与 check-outline 共用退出码，不是单独的脚本） |
| `check-density.mjs` | 0 | 1（低于硬下限的条数 > 0） |
| `repeated-numbers.mjs` | **永远 0** | 要它会失败得显式加 `--max=N` |
| `outline-inventory.mjs` | 盘点用，看输出不看码 | — |

`repeated-numbers.mjs` 默认不退 1 是因为**它不下判断，只摊账**。同数复用在本书是有意的母题，机器分不清哪次是母题哪次是撞车。

**章名比对不是新脚本，是 `check-outline.mjs` 里新加的两条**（2026-08-15，封掉下一节盲区表第一行）。它查两件事：章纲章名与正文章名是否一致、已写正文的章名有没有重复。**两条都只管已写正文的章**——未写的章，章纲里那个名字是工作标题，本来就允许与将来的成稿不同。改正文章名（含文件名）以后必须同步章纲，否则这里会报。

重名那一条是**跨卷查的**，因为触发它的第 23 章与第 36 章本来就分属卷一卷二，只在卷内查抓不到。但它同样只看已写的章：全书五卷现有 14 组重名章名，其中「收束」9 章、「第一次进去」7 章、「撞墙」6 章，都是排布用的功能性占位名，**把它们算成问题会让这条检查上线当天就得被关掉**。

**机检干净不等于没问题。** 人物动机、情节因果、伏笔有没有回收、有没有提前泄露谜团台账里排在后面的答案，机器一概不管。脚本的作用是把人从数字核对里解放出来，去干只有人能干的部分。

## 机检具体不查什么

上一节那句「不等于没问题」太笼统，接不住。下面这些是实际撞出来的，每一条都曾在 `npm run check` 全绿的树上存在过。**报「全绿」时要知道自己没证明什么。**

| 盲区 | 为什么漏 | 撞出它的那一次 |
| --- | --- | --- |
| ~~正文章名与章纲章名不一致~~ **已封（2026-08-15）** | 原因是两个表从不相互对照。**现由 `check-outline.mjs` 的章名比对封掉**，同时封掉了章名重复；见上一节。仍不查**未写章**的章名 | 第 23 章改名后章纲与细纲两处失配，四项全绿 |
| 相对时间副词 | 查的是登记过的绝对数值，「上个月」「去年八月」「这三年」不含数字 | 卷一时钟裂成两套，八处以上把相隔两三周的章说成去年 |
| 一行被邻近的替换吞掉 | 只查数值对不对，不查某一行还在不在 | 见 [parallel-sessions.md 的盲覆盖](./parallel-sessions.md) |
| 半角标点，当一侧是引号时 | 规则要求半角符号**两侧都是汉字** | `022:99`、`022:111` 两处半角逗号长期零命中 |
| 同一个毛病换一种措辞 | 禁用词是纯字面 `includes`，不是语义匹配 | 「三年」那批：机检报到两章，同样的错在另外六章里换了说法，只有写的人自己扫才找得到 |
| 时刻与时长对不上 | 脚本不做减法 | 第 55 章「十点二十」加「看了三个小时」，而下一个时间点是十一点十分 |

两条推论：

**加一条检查之前先确认它真的会命中。** 禁用词那条尤其容易做错——登「沾锈三年」一处都抓不到（正文里没有这四个连着的字），登「三年」误报十几处合法的刷锈年头。**一行给假安心的规则比没有那一行更危险**，它会让人以为这个方向已经守住了。同理，名词表里「目前还空着的数」那种主动给出的清单，出错的代价比一个数字写错大得多——下一个人会直接照它拿。

**看到报错的位置不在自己地盘，先想想同一个毛病在自己地盘里有没有。** 机检报的是句子，你要修的是毛病。

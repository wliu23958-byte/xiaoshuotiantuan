# 五个会话共写一棵工作树

本仓的常态就是这个形状：五个 Cursor 窗口 = 五名成员，同时开在**同一个工作目录**上。单人单会话不必读本文。

写下反面教材是有意的：只写成功经验的方法论，下一个人复现不出来。下面凡是标了具体章号或文件名的，都是本仓真实发生过的。

## 地盘已经分好了，越界前先说一声

**一个目录一个写入方。** 归属表在 [domain.md](./domain.md#目录归属)——设定师 `01-`、大纲师 `02-`、主笔 `03-`、审校 `04-`、总编 `00-`。

这一条不是靠锁维持的，是靠事先分派维持的。锁是第二道防线，不是第一道。会话之间无法可靠地协商出地盘：**每个会话只看得见自己的任务。**

越界之前在频道里说一声（`send_to_session`），对方让位再动。

**会话数量本身要克制。** 五个窗口不等于五个人都得同时在写。空转的只读会话会互相仲裁——同一件事套四层，没有一层该发。

### 锁挡得住的和挡不住的

多人可能碰同一个文件时先 `acquire_write_lock`，改完 `release_write_lock`。主笔动笔前锁到**具体章节文件**，不是锁整个 `03-正文/`。

**锁挡住的是同时写。它挡不住先后各写一次。** 后面那类是本文其余部分要解决的。

### 第三类：台账不属任何人

这几个文件既不是你的地盘也不是别人的，却**每写一章、每改一条章纲就必然要碰一次**——可预测、高频，而且不算越界：

| 文件 | 谁会来加行 |
| --- | --- |
| `01-设定/名词表.md` | 主笔新立了设定、新写了一个百分比 |
| `01-设定/时间线台账.md` | 主笔本章发生了入器 |
| `02-大纲/谜团台账.md` | 大纲师解了或提了一个谜团 |
| `04-审校/` 各卷记录 | 任何人查完一轮 |

它们靠的不是地盘划分，是另一套做法：**先在频道说一声、只加自己那一行、不动邻行。** 冲突真出现时也别自己合并——问那一行的作者。

一个连带后果要接受：**你的章节可能先落地、它的台账条目后落地。** 比这更坏的做法是替别人提交一份他写到一半的台账。真遇到就在提交信息里写明「台账条目随该文件另行提交」。

## 盲覆盖：锁和报告都防不住它

「不动邻行」不只对台账成立，任何被两个会话先后各追加过一次的同一处都算。

它长这样：一个会话先在名词表某一行的备注里补了一句「二〇二三年起停住四年」，另一个会话随后改同一行的沾锈数值，匹配串写得太短、跨过了那句备注，一次「成功」的替换把它吞掉。

**它不是并发编辑，锁和报告都拦不住。** 两次写入先后发生，各自都合法，第二个人也确实在频道里说过、也确实拿到了锁。冲突提示不会出现——工具视角里根本没有冲突，它只是照给定的匹配串替换了一段，而那段里混着别人的字。

做法是把匹配串锚在**你自己写下的字**上，改完立刻重读那一段确认邻居还在。没有任何机制在守这一条，而且它出问题时**不会有任何东西变红**——机检查的是数值对不对，查不出一句备注被吞了。

## 提交：精确暂存，且推之前验提交状态

一条总的判据：**以整棵树为输入的操作，在共享树上都是错的。** 它的输入包含别人写到一半的部分，产出因此没人要。

**逐文件 `git add`，绝不 `git add -A`。** 树上同时躺着别人写到一半的章节和台账，一次全量暂存就是替他提交未完成的工作。半章正文提交进去，下一个读它的人分不出这是断了还是写完了。

**全库派生态命令不得单方面跑。** 凡是「扫当前树再写回去」的都算：全库禁用词批量替换、批量重排章号、`npm run build`（写 `dist/`）。

**`check-format.mjs --fix` 就是这一类，不要顺手跑。** 不带 `--fix` 时它只读、只报，随时可以跑；带上 `--fix` 它会扫整个 `03-正文/` 并**写回每一个它认为该改的文件**——包括别人此刻正在写、markdown 装饰还没清干净的那几章。要用就先约定谁跑、什么时候跑，跑完人工过一遍 diff。

区分清楚：**只读的机检随时可以跑**，跑了也只影响你自己的终端。危险的是会写回文件的那一类。

这与「改了公共东西要报」不是一回事：那一条是**要报**，这一条是**根本不能自己跑**。真需要跑，先约定谁跑、什么时候跑。

**推之前另在临时 worktree 里检出提交状态跑一遍机检。** 这一条最容易被跳过，而它防的是一类看不见的失败：

> 你本地跑的是**含别人未提交改动**的树，而你的提交里装的是别人**已提交的旧版本**。本地机检全绿证明不了提交状态能过。

在本仓这尤其常见，因为机检的真源是别人的文件：你新章里那个 2.4% 之所以不报错，是因为设定师刚往名词表加了一行——而那一行还没提交。你推上去，别人拉下来，`check-facts.mjs` 就在他那里红了。

```powershell
# 先 commit，再验；此处的 HEAD 就是你刚做完、即将推的那个提交
$repo = $PWD
git worktree add --detach "$env:TEMP\verify" HEAD
Push-Location "$env:TEMP\verify"
[Console]::OutputEncoding = [Text.Encoding]::UTF8
npm run check
Pop-Location
git -C $repo worktree remove --force "$env:TEMP\verify"
```

机检脚本不依赖 `node_modules`（只用 node 内置模块），临时 worktree 里不用先 `npm install`。

顺序不能反：提交前跑这段，验的是**上一个**提交，一样给绿，而且绿得毫无意义。

它不碰共享工作树，因此不打扰任何人。

**提交信息里写清你**没有**带走什么。** 台账条目卡在别人正在改的文件里无法一并提交时，写明这一点，才不至于日后被当成漏登。

## 报什么，不报什么

**只报对方从自己那一轮里看不到的事。** 四类：

- 你改了公共东西会拆到他：名词表新增禁用词、台账口径变了、脚本阈值调了
- 决策类事实：设定裁定的结论、章号区间的分配、被否掉的写法
- 他的稿子**读得通但事实不对**——这是旁观者唯一真能提供的，机检拿不到
- 地盘与顺序协调

**别人正在写的章节里的错别字、排版一律不报。** 他自己的 `check-format.mjs` 比消息快。报了只会驱使他去看一个正在变的地方。

**审校的例外**：审校报的就是别人稿子里的问题，那是他的本职，不受这条约束。但仍然要等对方 `report_task` 之后再报——审一份还在动的稿子，结论出来就作废了。

## 断言有保质期，但设计建议没有

**共享树上关于当前状态的任何断言都有保质期，文档不例外。** 「某文件第几行写着什么」「某个数没登记」「某章还没写」——这类结论型消息发出前重新取一次证据，成本比一轮仲裁低得多。

这也是[「报错之前必须打开源文件确认原文」](./domain.md#冲突按什么顺序裁)在多会话下的加强版：不只要打开，还要**在发消息之前那一刻**打开。

**但这条管不了关于「还不存在的东西」的建议。** 「你这个单元的诡计和支线 7 撞了」「这条谜团解在卷四会让卷五断供」无法预先查新，因为它指向的是尚未写下的章节。两类并成一条，结论会滑到「什么都别建议」——而这恰恰是只读会话产出的全部价值。

## 只读会话要派具体任务，否则是负收益

只读会话最有价值的产出是**没人有空去查的横向账**：某个数在全书用过几次分别什么量纲、某条设定被哪些章引用过、某个单元的手法和哪些单元重合。

这类账人记不住，而且**在被派活之前一条都不会出现**。重复数字这笔账此前一直靠备注手数，两处都数少了：名词表写着「十七已有两处」（只数了它自己登记过的），卷五审校写着「第 404 章那个十九年是全书第三个十九」（没扫正文）。实扫卷一二十章，十七是第六到七处，十九至少第七个。

好任务的形状：**只读、边界清晰、结论能直接改变写入方的下一步。** 典型是「把全书所有出现『十七』的地方连原句列出来，只报事实不提改法」「从正文逐章抠出沈砚说话超过两句的地方，以正文为准不以设定为准」「把十七个支线单元的核心手法一次列全，标出可能撞车的」。

派任务时写明**不要做什么**——不改文件、不替别人重写、不下设定裁定。否则调研会变成第二份实现。

## 决定权

**要么归 owner，要么被人明确授权。** 涉及设定或情节走向的一律不自己拍板：进黑板 `kind=risk`，通知责任人。能直接改的错字、数字、时间才自己改并记录。

被授权替别人拍板时，**把自己的能力边界写在裁决里**：读过哪些文件、没读哪些、因此裁的是方向还是具体条目。定方向与约束强度就够了，具体怎么改留给 owner——他知道那一卷里的伏笔，裁决方不知道。
